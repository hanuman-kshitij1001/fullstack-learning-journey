## Backend Implementation Details

The backend sections of the repository are divided into Node.js runtime operations, Express servers, REST architecture, and SQL database management.

### 1. Node.js Core Fundamentals
- **Process Context**: Commands utilize `process.argv` to capture input arguments from the shell.
- **CommonJS Module System**: Modules are separated using `module.exports` and loaded using `require()`. Aggregate exports are taught using a folder's `index.js` file to bundle multiple sub-files (like Fruits/Names scripts) as a single importable package.
- **Npm & Dependency Scopes**: Initializing project manifests using `npm init`, installing node packages, and organizing local vs global executable libraries.

### 2. Express.js Server Framework
- **Routing Engine**: Routing endpoints utilizing HTTP `GET` handlers (`app.get()`) to manage client navigation requests.
- **Path and Query Parsing**: Reading path parameters using variables via `req.params` (e.g. `/:username/:id`) and querying inputs using `req.query` variables.
- **Templating with EJS**: Setting up EJS (`app.set("view engine", "ejs")`), designating view folders, interpolating variables into static files, rendering server-side logic (loops and conditionals), and including shared template components (header, footer headers).
- **Static Assets Middleware**: Serving stylesheets, pictures, and frontend JavaScript scripts using `express.static()` middleware.

### 3. RESTful API Design & Payload Parsing
- **Middleware Parsing**: Integrating `express.urlencoded({extended: true})` to parse incoming HTML form submissions and `express.json()` to accept incoming JSON payloads.
- **RESTful Mappings**: Structure mappings for CRUD entities (represented in the Posts app):
  - **Index**: `GET /posts` to view all elements.
  - **New**: `GET /posts/new` to get a form for creation.
  - **Create**: `POST /posts` to add a new post to the resource array.
  - **Show**: `GET /posts/:id` to retrieve details of a specific item.
  - **Edit**: `GET /posts/:id/edit` to retrieve a form pre-populated with data.
  - **Update**: `PATCH /posts/:id` to modify data on the server.
  - **Destroy**: `DELETE /posts/:id` to delete the item from the collection.
- **Method Overrides**: Using the `method-override` middleware to allow forms to send HTTP `PATCH` and `DELETE` requests using query parameter markers (`?_method=...`).
- **State Navigation**: Implementing `res.redirect()` to forward users to safe view pages following modifying operations (POST/PATCH/DELETE).

### 4. Relational SQL Databases
- **SQL Schemas**: Generating databases (`CREATE DATABASE`) and tables (`CREATE TABLE`) with structured fields.
- **Schema Constraints**: Enforcing data integrity at database insertion using schema constraints (`NOT NULL`, `UNIQUE`, `DEFAULT` values, and logic validation `CHECK`).
- **Relational Keys**: Using Primary Keys (`PRIMARY KEY` on a user's ID) and Foreign Keys (`FOREIGN KEY` mapping a post's `user_id` to a user's `id`) to model real-world relationships.
- **Relational Operations**: Executing row additions (`INSERT INTO`), filtering rows (`SELECT`, `WHERE`), managing results (`LIMIT`, sorting `ORDER BY`), and running updates/deletions.
